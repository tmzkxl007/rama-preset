# 넷플릭스 자막 규격 (2026-09-25 도입)

출처
- Timed Text Style Guide: General Requirements — https://partnerhelp.netflixstudios.com/hc/en-us/articles/215758617
- Korean Timed Text Style Guide — https://partnerhelp.netflixstudios.com/hc/en-us/articles/216001127
  (General 문서에는 글자 수·읽기 속도가 없다. 한국어 수치는 Korean 문서에 있어서 같이 쓴다.)

## 규칙 — 검사기 코드와 같은 번호

| 코드 | 규칙 | 수치 |
|---|---|---|
| G1 | 자막 한 장 최소 표시 시간 | **5/6초 (0.83초)**. 24fps 기준 20프레임 |
| G2 | 자막 한 장 최대 표시 시간 | **7초** |
| G3 | 줄 수 | **한 줄** (사용자 지정 2026-09-25). 넷플릭스 원 규격은 최대 2줄이지만 우리는 두 줄을 쓰지 않는다 |
| G4 | 위치 | **가운데 정렬**, 화면 위나 아래. 화면 속 글자와 겹치면 옮긴다 |
| K1 | 한 줄 글자 수 | **16자**. 라틴 문자·숫자·공백·문장부호는 0.5자로 센다 |
| K2 | 읽기 속도 | **초당 12자** (어린이 9자). K1과 같은 방식으로 센다 |
| K3 | 줄 끝 문장부호 | 줄 끝에 **마침표·쉼표를 쓰지 않는다**. 두 문장을 한 장에 넣을 때만 문장 사이에 쉼표 |
| K4 | 말줄임표 | **`…` 한 글자**(U+2026). `..` 나 `...` 는 쓰지 않는다. 한 문장이 두 장에 걸쳐 이어질 때는 말줄임표·대시를 붙이지 않는다 |
| K5 | 이탤릭 | **쓰지 않는다** |

자막 나누기(General): 한 줄이라 줄을 바꾸지 않고 **다음 장으로 넘긴다**. 넘기는 자리는 문장부호 뒤, 접속사·조사 앞.
이름과 성, 수식어와 명사, 동사와 부정어, 숫자와 단위는 서로 다른 장으로 떼지 않는다. 두 사람 대사는 한 장에 넣지 않고 장을 나눈다.

넷플릭스 규격에서 자막 대상이 아닌 것: 화면에 계속 떠 있는 제목·크레딧·로고 문구, 벡터 도형.
검사기는 ASS 스타일 `H1/H2/HL1/HL2/Title/CREDIT*`와 `\p` 도형을 건너뛴다.

## 검사

```
python scripts/netflix_sub_check.py <captions.ass 또는 작업 폴더>      # 위반 줄까지 출력
python scripts/netflix_sub_check.py --quiet <폴더>                        # 파일마다 한 줄 요약
```

위반이 있으면 종료 코드는 1이다. **지금은 경고 단계다.** 납품을 막지 않고, 결과를 보고 고친다.
이미 만든 편에 돌려 보면 전부 걸리기 때문이다. 아래 '이 프리셋에서 걸리는 것'을 보라.
빌더가 규격대로 뽑게 바뀌면 그때 불합격 단계로 올린다.

## 고치는 방법 (우선순위)

1. **G1 짧은 자막** — 뒤에 빈 시간이 있으면 끝 시각만 0.83초까지 늘린다(음성은 그대로라 싱크 영향 없음).
   빈 시간이 없으면 **이웃 조각과 합친다**. 합친 글이 16자를 넘으면 **합치지 않는다**(두 줄 금지).
   그때는 앞 조각을 조금 일찍 띄우거나(앞 자막 끝을 당김) 그대로 두고 경고로 남긴다.
2. **K2 읽기 속도** — 거의 다 G1과 같은 조각이다. G1을 고치면 대부분 같이 풀린다.
   그래도 남으면 글을 **줄이거나 지운다. 다른 말로 바꾸지는 않는다**(넷플릭스: paraphrase 금지).
3. **K3·K4** — 줄 끝 `.` `,` 지우기, `..` `...` 을 `…`로 바꾸기. 글자만 바꾸는 것이라 바로 적용한다.

## 이 프리셋에서 걸리는 것 (라마 · 2026-09-25 실측)

`~/rama_work/*/captions.ass` 38편, 자막 1452장(나레 `NARR` 280 · 대사 `CAP` 1172)에 돌린 결과:

| | 장수 | 설명 |
|---|---|---|
| 위반 있는 자막 | 426장 (29%) | 전부 통과한 편은 0편 |
| G1 0.83초 미만 | 416장 | 대사 337장 · 나레 79장. 대사는 `DLG_CHUNK = (5, 10)`, 나레는 `NARR_CHUNK = (4, 8)` 로 잘게 끊는다 |
| K2 초당 12자 초과 | 30장 | 거의 G1과 같은 조각 |
| K1 16자 초과 | 5장 | 예: `'근데 왜 아까는 관등성명도 안 대신'` (16.5자) |

**적용하면 바뀌는 것**
- 짧은 자막 416장 중 **232장은 끝 시각만 늘리면 된다**(뒤에 빈 시간이 있음, 싱크 영향 없음).
- 184장은 이웃 조각과 합쳐야 한다. 161장은 16자 안이라 한 줄로 합친다(한 편에 평균 4장쯤 준다).
  **23장은 16자를 넘어서 합치지 않는다**(자막은 한 줄 — 2026-09-25 사용자 지시).
- 자막은 이미 **전부 한 줄**이다(나레·대사 모두). `spec.py` 의 `DLG_LINES`·`CAP_MAXLINES` 도 1로 맞췄다.
- K1 16자 초과 5장은 한 줄 규칙 때문에 두 장으로 나눠야 한다.
- 이 대사 자막은 원래 대사를 그대로 옮긴 것이라 K2를 맞추려고 글을 줄일 때는 **줄이거나 지우기만** 하고 다른 말로 바꾸지 않는다.
- 문장부호(K3·K4)는 이미 규격 안이다.

## 빌더 자동 적용 (2026-09-25 · 새로 만드는 편부터)

사용자 지시로 **앞으로 만들 편**에 자동으로 들어간다. 이미 만든 편은 다시 굽지 않는다. 포레이로와 같은 방식이다.
- `presets/라마/netflix_sub.py` — 규칙 코드
- `chunks()`(build.py·align.py): 꾸미는 말·부정어 뒤에서 안 끊는다("기현을 / 제 집으로")
- `align.py`: 0.83초 못 되는 나레 덩이를 낱말 시각으로 다시 나눈다(`|` 로 직접 자른 마디는 그대로). build.py 는 narr_align.json 의 덩이 글을 쓴다
- `build.py`: captions.ass 쓰기 직전 `fix_ass` — 문장부호 · 끝 늘리기 · 0.10초 안 당기기 · 이어진 옆 장과 한 줄로 합치기. 남으면 `[라마 규격 위반]`
- 시험(sb37 복사본으로 align→build 전 과정): 합침 5 · 시간 조정 14 · 남은 짧은 자막 2장(`|` 로 직접 자른 "후임들은", 대사 "그래도 같이")
